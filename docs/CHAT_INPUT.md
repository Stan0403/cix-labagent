# 按问题提供聊天输入

Qwen3-4B、CPU推理服务、行动决策协议及实验事实核验规则保持原有配置。

读数、进度、记录状态和采样次数问题直接从当前实验记录回答，不调用LLM。例如“现在多少伏？”“测到多少了？”“刚才读数是多少？”共享同一条查询路径。候选值不能当作正式测量；只有第一帧时明确说明等待第二次采集，未记录。失效候选不当作当前电压，重测替代的测量不作为最新有效结果。异常报告与暂停指令优先处理，不被读数快答覆盖。

原理解释按问题检索少量手册片段，保留真实来源与行号；记录问题不自动附加手册。模型只接收相关步骤、候选/确认/保存状态及有限阻塞原因，不接收完整计划、图像、检测框、原始模型输出或整个事实字典。独立问题不带历史，明确追问最多携带最近两条短消息。`get_status` 返回同样的精简记录，`search_manual` 也限制片段长度。

固定助手说明放在首个system消息，动态记录、检索和问题放在末尾user消息；只有问题需要时才提供动作建议或采样调整工具。普通聊天显式传递`cache_prompt=true`与关闭思考参数。服务原有默认缓存并非此前完全关闭，因此需要分别看输入缩减、连续聊天复用及聊天/行动交替后的实际缓存命中，不能把所有收益归因于新增参数。缓存仅复用模型计算，现场状态仍在每次请求时重新读取。

对话模型调用的耗时、输入字符数、token用量及llama.cpp缓存时序保存在`chat.model_call`审计事件，不记录额外的完整提示词。发送问题后，页面立即显示问题及等待回复状态；完成后按服务器消息核对，避免重复气泡。切换实验会取消浏览器等待并丢弃旧页面结果。

性能测试使用正式Qwen服务与只读实验快照，不向正式实验写测试数据。需区分模型首个文本输出、完整响应和页面显示时间；短输出测速不代表完整答案质量。实际数据见项目根目录`chat_optimization/2026-11-24/`。
