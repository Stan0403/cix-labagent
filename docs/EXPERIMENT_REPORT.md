# 实验报告导出

实验页面的“下载图文报告”导出单个 HTML 文件，可在浏览器直接打开、打印或自行保存为 PDF。现场图片嵌入文件内，无需配套图片目录，不调用模型重新编造实验过程。“文字版”导出相同结构的 Markdown 正文；CSV/JSON 仍作为独立数据下载功能保留，不加入报告正文。

报告固定八项：基本信息与结果摘要、简要目的与依据、器材与仪表设置、实际过程、测量数据与现场图像、数据分析、异常与人工修正、结论与完成情况。没有附件章节，也不直接输出模型答复、内部字典、候选标识、哈希或逐条技术审计。

生成原则：

- 目的取已确认计划中的简短描述；依据注明指导材料或输入目标，不复制整份文档。
- 过程只整理实际确认、核验、保存、暂停与重测等记录，计划步骤本身不作为已完成证据。
- 数值统计仅采用已保存且未被替代的测量。未保存记录、重测替代记录和人工修正分别说明。不同单位分别统计；单样本不作重复性分析，缺少精度资料不计算不确定度。
- 每个样本的量程取其关联候选或采样之前的设置，避免把后续新档位写到旧读数上。结束时间取实际完成事件，不使用后续无效请求更新的会话时间。
- 两帧稳定核验必须有对应的两条记录、不同图像、至少1秒间隔、同量程和允许差值；不把两帧算作两个独立样本。旧记录缺少细节时明确说明。
- 图片使用已留存的现场画面，显示屏可按保存的 ROI 作无损裁剪。正文最多展示12幅、测量图像最多前4组，表中仍保留全部有效样本；图片缺失时保留文字记录并说明未能载入。
- 软件演练显著标记为“非真实测量”；未结束、暂停或样本不足时不生成“目标已完成”的结论。缺失信息标为未记录，不补写仪表型号、精度或修正原因。

接口：`GET /api/sessions/{id}/export?format=html` 为图文版，`format=md` 为文字版；既有 JSON/CSV 接口保持。导出只读取记录和图像，不更改实验状态。

实现：`report_data.py` 将已存记录整理为八项内容，`report_rendering.py` 共用这些内容生成图文/文字版本，`report.py` 保留原导入入口及 CSV 功能。

验证入口：`python -m pytest tests/test_readable_report.py`；`scripts/verify_readable_report.py --output <独立目录>` 生成明确标记的软件演练样例并检查 Chromium 排版。增加 `--image-dir <正式图片目录>` 时，只读已有会话生成样例，不创建实验或测量。
