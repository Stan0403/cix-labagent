# 实验页面：自动推进与单一主操作

2026-11-27更新：当前主读数入口在点击“已接好，开始读数”后先倒计时5秒，再执行快速定位和单帧识别；按计划范围记录实际符号，零值/负值提示核对。器材检查仍保留两次正式独立观察。下文较早的双帧读数描述属于兼容入口，当前行为见根README与CURRENT_STATE.md。

页面顶部固定显示当前步骤、正在执行的工作、等待原因和最近更新时间。需要人处理时只显示一个主按钮；暂停始终可见。点击具体确认按钮会记录该事项并在条件满足时进入下一步，不再先勾选通用确认框。

开始实验时，操作人员核对计划后点击“按此计划开始”，合并计划审核、阅读要求与启动；待澄清事项和未填写的测量单位仍阻止启动。

## 自动与人工

- 器材：预览仅更新检测框，不写实验事实。正式观察的两张不同图像必须相隔至少 1 秒、每张所有必需器材均明确可见，才记录自动核验；正帧在最多 90 秒的窗口内有效，任何缺失/未知结果清空连续正帧。重复图片不能通过。结果来源保留为视觉，不伪装成人工确认。
- 档位、插孔、接触和收尾：沿用当前计划对应的视觉规则。看不清时提示调整画面；也可展开“人工处理 / 详细信息”改为人工核对。没有自动适配器的步骤直接显示明确的人工操作。
- 读表：沿用两张独立画面、至少 1 秒间隔、同量程、差值不超过 0.02 V 的检查。满足样本数后自动保存并继续；候选与正式记录仍区分。
- 人工修正器材：展开修正清单会暂停自动检查，按实际情况修改后使用顶部“提交器材清单并继续”。缺少器材不能因点击确认而跳过。
- 暂停恢复：点击暂停后保留步骤；核对现场后在顶部恢复。确认过期时必须重新核对。切换浏览器后台暂停后续自动调度，回到前台重新同步状态。

状态展示区分决策、识别、读表、保存、等待现场、等待人工、重试、暂停、错误和完成。长请求显示真实已用时间，不展示虚构完成百分比。相机权限失败时，顶部显示可操作的重试入口。

## 开发接口

`Engine.view()` 的 `interaction` 是规则生成的当前任务说明，包含 `step_id / position / total / phase / message / primary_action / updated_at`。前端只在其上叠加相机请求、网络中断、人工编辑等浏览器状态；已完成/已暂停状态优先于旧请求回调。

`Action.advance_after` 默认 `false`，兼容既有客户端。新页面在人明确点击本步确认时传 `true`；服务端在同一事务中记录确认并检查推进条件，未满足则停留。它不能用来自动确认物理状态，也不适用于任意动作。

`equipment_stability` 保存正式观察的两张图像摘要、采集时间和后端来源。`objects` 的视觉来源只有在关联的多帧证明有效时才满足器材 gate。导入实验中的手动检查和测量范围仍生效。

回归：`python -m pytest tests`；前端状态检查：`node tests/test_task_status.cjs` 和 `node tests/test_equipment_live.cjs labagent/web/equipment-live.js`。`scripts/browser_task_smoke.py --output <独立结果目录>` 使用 Chromium 假摄像头和明确标注的模型 fixture，覆盖自动链路、暂停刷新恢复、单次人工确认、相机拒绝及重试、移动端布局；不代表真实模型准确率，也不写正式实验数据库。
