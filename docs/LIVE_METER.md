# 仪表设置检查：首次自动，之后点击重试

2026-11-27更新：未定位或仪表细节过小时，页面在有限窗口内重新取帧定位；实际模型仍对一次有效快照的旋钮、插孔分别推理。每个局部模型请求超时现为30秒。本轮两次完整模型接口采样为10.871和11.135秒，见evidence/board_refresh/2026-11-27/model-benchmark.json。

仅对已审核计划中自动视觉核对的 `meter_setup` 步骤生效，`LABAGENT_METER_LIVE_ENABLED` 默认关闭。开启后，首次进入该步自动检查一轮；未通过、看不清、画面变化、服务异常或繁忙时停止，显示原因和“重新检测仪表设置”按钮。只有点击按钮才再检查一轮。通过后仍在同一事务中核验当前画面并进入下一步。其他步骤及手工核对入口保持原行为。

每轮只截取一张照片，旋钮与插孔从该照片分区识别；视频仅用于取景，后续视频变化不会撤销本轮照片结果。识别始终单请求在途，快速双击不能发出重复检查。失败结果、识别照片和放大图保留到下一次检查或切换、暂停。页面显示本次照片时间与真实耗时。

同一标签页使用 sessionStorage 记录会话、步骤是否已尝试，刷新、暂停恢复或重新进入历史实验不会清除该标记。已有本步检查记录的老实验直接显示重试按钮。这个标记只控制请求调度，不代表检查通过；服务端的证据、版本和当前画面校验保持原有约束。

模型路径为已有YOLO NPU定位仪表 → 取仪表区域 → CIX NPU视觉编码（固定320像素输入）→ CPU生成受约束短回复。输出严格解码为黑笔COM、红笔V/Ω、直流档及量程，程序据本实验范围判断量程是否足够。只看到一台且仪表区域足够清晰才调用模型；看不清、unsupported档位或无仪表时不自动通过。NPU服务不可用时提示重试/人工核对，不静默退回原来约78秒的CPU检查。

预览不会修改实验状态。只有四项均通过才签发会话、步骤、版本和时效绑定的token。页面采用该照片结果时不再拍第二张图，也不再因视频变化而要求重拍。token过期/丢弃、暂停、切换、删除或版本变化，仍不能写核验或推进。成功时仅保存本次识别照片、裁剪区域、拍摄及采用时间，方法明确标记为 `single_frame_snapshot`，不标记成当前现场或两帧核验。结果仅描述拍照时状态，之后调整仪表需重新拍照；模型不能证明硬件电气接触。

适配器配置 `LABAGENT_METER_VLM_SERVER=http://127.0.0.1:8034`，并依赖已安装的 `labagent-demo-equipment-vlm` 与 `labagent-demo-npu-vision` 服务。视觉编码器仍使用现有模型权重；读表仍用既有OCR。

接口：`POST /api/sessions/{id}/meter-live/preview`（file）、`.../discard`（preview_id）、`.../accept-snapshot`（JSON preview_id）。旧 `.../commit` 仍保留前后画面比较以兼容旧客户端，当前页面使用单帧采用接口。

验证入口：`tests/test_live_meter.py`、`tests/test_meter_npu_route.py`、`scripts/browser_meter_live_smoke.py`。浏览器测试使用明确标记的独立模型/视频fixture，覆盖处理中换帧、当前帧提交、暂停刷新恢复及删除；不代表真实模型识别准确率。
