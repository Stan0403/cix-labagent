# O6 键盘拍照采集

在 **O6 自己的桌面**双击“液晶数据采集”，浏览器打开 `http://127.0.0.1:8766/`。
点击“打开摄像头”并允许权限，摆好万用表后按 **空格键**保存一张照片。
长按空格只保存一次；每次松开再按保存下一张。保存期间不排队拍摄。
按 Esc 关闭摄像头。关闭网页也会释放该页面的摄像头。

如果出现摄像头占用提示，先关闭原实验网页正在使用的摄像头，再回到采集页打开。
有多个摄像头时，在摄像头关闭状态下从下拉列表选择，再点击打开。
浏览器运行在哪台设备，就使用哪台设备的摄像头；本工具应在板子的浏览器中操作。

## 标签与批次

- 默认“待标注”：只管按空格拍照，后续统一核对标签。
- “可读数字”：按屏幕原样输入，例如 `1.353`、`-0.012`、`.001`、`00.3`。
  输入后按 Enter 离开输入框，随后可以连续按空格拍同一读数。更换读数后更新标签。
- “空屏”：标记没有数字的画面，标签是空字符串，不标为零。
- “看不清”：模糊、反光、遮挡等无法辨认的画面，标签保留未知，不当作空屏或零。
- “超量程”：记录实际显示的 `OL`、`1` 等字符，类型单独保留，不直接当成电压读数。
- 备注可填写量程、光照、视角等。输入框中的空格正常输入，不触发拍照。
- 不同时段重新拍摄时点击“新建拍摄批次”。新批次会清空旧读数，恢复待标注。
  刷新同一标签页会继续当前批次，但不会自动重新打开摄像头。

## 照片位置

桌面的“液晶采集照片”文件夹快捷方式指向：

```text
/home/radxa/referenced-chatgpt-conversation-this-is-an/LabAgent-demo/data/ocr-capture/
```

每个批次单独一个目录：

```text
20261122_190000_ab12cd34/
  batch.json          # 批次备注、创建时间
  images/*.jpg        # 原采集分辨率的完整画面，JPEG 质量 98%，没有界面文字或水印
  records/*.json      # 一张照片对应一份标签、类别、像素尺寸、SHA-256、备注
```

页面可下载本批 `manifest.jsonl`，它由图片记录实时汇总，原始记录保存在板上。
未知标签为 JSON null，空屏标签为 `""`；数字保留字符串，不能提前转成浮点数。
每条记录的 `group` 是拍摄批次，`review_status` 默认 `pending`。后续人工核对后再进入训练，
按整批划分训练、验证和测试，避免把相邻帧分到不同集合。

## 运行方式

桌面入口通过用户服务按需启动，不需要重启比赛项目：

```sh
systemctl --user start labagent-lcd-capture.service
systemctl --user status labagent-lcd-capture.service
journalctl --user -u labagent-lcd-capture.service -n 40 --no-pager
```

也可在项目根目录直接运行：

```sh
.venv-app/bin/python scripts/lcd_capture.py --open-browser
```

默认只监听本机 127.0.0.1:8766。使用现有 `.venv-app` 的 FastAPI、Pillow、Uvicorn，
采集页由浏览器读取摄像头，不需要 OpenCV 图形窗口、GPU 或 NPU。
不运行识别，不写正式实验数据库，也不改动已有 YOLO 器材照片目录。

## 验证记录

- 19 项后端检查通过：原图片字节、尺寸和标签保留，空屏/未知区分，坏图和错误标签拒绝，
  同编号重试不重复、冲突重试拒绝，并发保存记录完整、批次记录导出和同源写入。
- 独立 Chrome 虚拟摄像头端到端测试通过：空格、长按去重、单请求保存、
  画面与标签同步冻结、输入焦点保护、1920×1080 保存、刷新恢复批次和移动端布局。
- 自动化测试照片只进入独立临时目录，不进入正式采集数据集。
- O6 安装证据和服务检查由 `ocr_training/capture-tool/` 保存；实际相机权限首次打开时由用户确认。
